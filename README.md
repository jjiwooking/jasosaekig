# Career Essay AI v0.4.1

한 기업의 지원서를 하나의 워크스페이스에서 완성하는 Streamlit + Supabase 자기소개서 프로그램입니다.

## 화면 구조

메인 흐름은 두 단계만 보여줍니다.

**① 지원기업 분석 → ② 자소서 작성**

기업분석, 기업 내 직무분석, 실제 채용분석은 사용자에게 따로 요구하지 않습니다. `지원기업 분석 시작` 한 번으로 내부에서 웹자료를 수집하고 하나의 분석으로 통합합니다.

보조 정보는 상단의 세 메뉴에 정리합니다.

- **지원서**: 지원기업 분석 → 자소서 작성
- **내 경험**: 이력서, Candidate Profile, Experience DB, 문체
- **보관함**: 최종 자소서, 분석 원문/출처, 검색 사용량, AI 지시 이력

## 핵심 동작

### 1. 지원기업 분석

기업명/직무/팀을 기준으로 다음을 자동 수행합니다.

1. Supabase 검색 캐시 확인
2. 필요한 경우에만 Tavily Basic Search
3. 기업 공식자료·최근 이슈·채용/직무 자료 저장
4. Gemini가 기업 + 직무 + 채용의도를 한 번에 분석
5. 자소서에서 써야 할 핵심만 화면에 요약
6. `이 분석으로 자소서 작성하기`로 즉시 다음 단계 이동

기업자료 캐시 30일, 직무/채용자료 캐시 7일을 사용합니다.

### 2. 자소서 작성

1. 기업의 자소서 문항을 모두 입력
2. 문항별 `내가 하고 싶은 말` 입력 가능
3. `전체 문항 분석 + 소재 배분`
4. Question Requirement Gate로 문항의 하드 조건 확인
5. Experience DB와 전체 문항을 함께 보고 소재 선배분
6. 의미상 중복 차단
7. 문항별 `자소서 완성하기`
8. Writer → Recruiter Reviewer → Fact Checker → Human/Final Editor 자동 실행
9. 소제목 포함 최종본 저장

## 프롬프트 원칙

- 문항을 지원자에게 유리하게 해석하지 않고 채용담당자 관점에서 냉정하게 분석
- `내가 하고 싶은 말`은 버리는 후보 소재가 아니라 반드시 보존할 사용자 의도
- Verified / Inferred / Unknown 분리
- 없는 수치, 성과, 경험 생성 금지
- 팀 성과를 개인 성과로 변경 금지
- 같은 전공·자격증·경험을 표현만 바꿔 반복하는 것 차단
- 합격 자소서는 문구가 아닌 구조·정보배치·리듬만 참고
- AI 말투, 추상 수식어, 기계적 연결어 감소

자세한 프롬프트 구조는 `PROMPT_SYSTEM_DESIGN.md`를 참고하세요.

## 503/429 대응

Gemini가 일시적으로 혼잡할 경우:

- 기본 모델에서 최대 3회 지수 백오프 재시도
- 웹검색 결과와 Supabase 근거는 그대로 유지
- 화면의 **AI 분석만 다시 시도 (웹검색 없음)** 버튼으로 Tavily 크레딧 없이 재분석
- fallback 모델은 임의로 하드코딩하지 않으며, 실제 사용 가능한 모델을 사용자가 `GEMINI_FALLBACK_MODELS`에 지정한 경우에만 사용

## Streamlit Secrets

```toml
GEMINI_API_KEY="..."
SUPABASE_URL="https://....supabase.co"
SUPABASE_SECRET_KEY="sb_secret_..."
TAVILY_API_KEY="tvly-..."
```

선택:

```toml
GEMINI_MODEL="gemini-3.6-flash"
# 실제 계정에서 사용 가능한 모델만 지정
GEMINI_FALLBACK_MODELS="..."
```
